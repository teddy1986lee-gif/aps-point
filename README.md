# APS 포인트 교환 · 간편 웹 버전 2.0.1

APS 회원이 웹사이트에서 문자 인증으로 로그인해 포인트를 확인하고, 연결한 풀팟 계정으로 토너먼트 티켓(40P당 1장)을 **신청 즉시** 받는 서비스입니다. 운영팀은 관리자 페이지에서 회원과 포인트를 등록하고, 풀팟 응답을 받지 못한 지급만 확인합니다.

| 구성 | 주소 | 내용 |
|---|---|---|
| 회원 웹사이트 | `/` | PC·휴대폰 겸용. 메뉴: 내 포인트 · 티켓 교환 · 교환 내역 · 풀팟 계정 |
| 관리자 페이지 | `/admin/` | 메뉴: 티켓 지급 · 풀팟 계정 · 회원·포인트 · 포인트 등록 · 설정 |
| 서버 | `server/` | Node.js 내장 기능만 사용(외부 패키지 없음), DB는 SQLite 파일 하나 |
| 브라우저 데모 | `dist/aps-web-demo.html` = 맨 위 `index.html` | 같은 서버 코드를 브라우저 안에서 돌리는 한 장짜리 체험판(모의 풀팟) |

**체험판을 링크로 열기(GitHub Pages):** 저장소 **Settings → Pages**에서 Branch를 `main`, 폴더를 `/ (root)`로 저장하면 1~2분 뒤 <https://teddy1986lee-gif.github.io/aps-point/>에서 체험판이 열립니다. 무료 계정은 Public 저장소에서만 Pages를 쓸 수 있습니다. 맨 위 `index.html`은 `npm run build:demo`가 `dist/aps-web-demo.html`과 함께 만듭니다.

## 1. 바로 실행해 보기

**필요한 것:** Node.js 22.13 이상(24 LTS 권장). `npm install`은 필요 없습니다.

```bash
npm run seed:demo          # data/aps.db에 예시 데이터 넣기 (다시 넣으려면 -- --reset)
DEV_EXPOSE_OTP=1 npm start
```

- 회원 웹사이트: <http://localhost:3000/>
- 관리자 페이지: <http://localhost:3000/admin/> — 아이디 `admin`, 비밀번호 `demo-pass-2026`

개발 모드에서는 문자가 실제로 나가지 않고 서버 콘솔에 찍힙니다. `DEV_EXPOSE_OTP=1`이면 인증번호가 화면에도 보입니다(운영 모드에서는 무시). 풀팟은 모의 풀팟(`FULPOT_MODE=mock`, 개발 기본값)으로 돌고 실제 티켓은 지급되지 않습니다. Windows 명령 프롬프트에서는 프로젝트 폴더에 `DEV_EXPOSE_OTP=1` 한 줄짜리 `.env` 파일을 만들고 `npm start` 하세요.

| 예시 회원 | 휴대폰 | 상황 |
|---|---|---|
| 이형주 | 010-1234-5678 | 120P, `teddy123` 연결 → 바로 교환(3장) |
| 김민준 | 010-2222-3333 | 150P, 풀팟 미연결 → `minjun_k`를 넣으면 바로 연결 |
| 박서연 | 010-3333-4444 | 39P, 1장까지 1P 부족 |
| 송하은 | 010-2468-1357 | 관리자가 직접 등록한 회원(`WEB-00001`, 80P) |
| 최지훈 | 010-4444-5555 | 같은 이름·번호 기록 2건 → 로그인 대신 운영팀 확인 안내 |

관리자 페이지 [티켓 지급]에는 윤태호 회원의 3장 신청이 풀팟 응답을 받지 못한 **확인 필요** 예시로 들어 있습니다. 정다은 회원은 운영팀이 연결을 해제한 예시입니다.

모의 풀팟에 '있는' ID는 `server/fulpot.js`의 `MOCK_ACCOUNTS`입니다(`minjun_k`, `seoyeon_p`, `haeun_s`, `fulpot_demo` 등). `seyoung5`는 이용 제한 계정이라 지급이 거절됩니다. 응답 없음 상황을 개발 서버에서 보려면 `FULPOT_MOCK_ISSUE=lost`(지급됐지만 응답 없음) 또는 `down`(요청이 닿지 않음)으로 서버를 켜세요. 브라우저 데모에서는 위쪽 [모의 풀팟 응답] 버튼으로 바꿉니다.

## 2. 회원 흐름

**풀팟 계정 연결 (풀팟 계정 메뉴)**
1. 풀팟 ID를 넣고 [계정 확인]을 누르면 서버가 풀팟에서 계정을 찾아 닉네임을 보여 줍니다.
2. [이 계정으로 연결]을 누르면 그 자리에서 연결됩니다. 운영자 승인은 없습니다(서버가 풀팟에서 한 번 더 확인).
3. 풀팟에 없는 ID, 이미 다른 회원에게 연결된 계정, 풀팟 확인이 안 될 때는 연결하지 않고 이유를 안내합니다.
4. 다른 계정으로 바꾸면 이전 연결은 해제 기록으로 남습니다. 이미 받은 티켓에는 영향이 없습니다.

**티켓 교환 (티켓 교환 메뉴)**
1. 장수를 고르고 받을 계정을 확인한 뒤 [티켓 n장 바로 받기]를 누릅니다.
2. 서버가 포인트를 확인하고 풀팟에 바로 지급을 요청합니다. 결과는 세 가지입니다.

| 결과 | 회원 화면 | 포인트 |
|---|---|---|
| 지급 완료 | 풀팟 지급 번호 표시 | 차감 |
| 지급 실패(풀팟 거절) | 사유 표시, 다시 신청 가능 | 그대로 |
| 지급 확인 중(응답 지연·통신 오류) | "확인하고 있습니다", 결과가 나오면 화면이 저절로 바뀜(몇 초마다 확인) | 사용 대기(돌려주지 않음) |

## 3. 관리자 흐름

**티켓 지급**
- 평소에는 할 일이 없습니다. 풀팟 응답을 받지 못한 신청만 **확인 필요**에 남고 메뉴에 건수가 뜹니다.
- 서버가 1분마다 풀팟 지급 기록을 신청번호로 조회해, 지급된 것은 저절로 완료로 바꿉니다.
- 직접 처리할 때:

| 버튼 | 하는 일 |
|---|---|
| 풀팟에서 확인 | 신청번호로 풀팟 지급 기록 조회. 있으면 바로 지급 완료 |
| 다시 요청 | 같은 신청번호로 다시 지급 요청. 이미 지급됐다면 풀팟이 다시 주지 않음 |
| 지급 번호로 완료 | 풀팟 관리 도구에서 지급을 직접 확인했을 때 지급 번호를 넣어 완료 |
| 지급 실패 처리 | 사용 대기 포인트를 다시 사용 가능으로 돌리고 사유를 회원 화면에 표시. 처리 직전에 풀팟 기록을 다시 조회해, 지급돼 있으면 실패 대신 완료로 바꿈. 풀팟 조회가 안 되면 막고, 풀팟 관리 도구로 미지급을 직접 확인했다고 체크해야 처리 |

**풀팟 계정** — 연결된 계정 목록(풀팟 ID·닉네임·풀팟 내부 번호)과 해제 기록. 잘못 연결됐거나 분실·양도 문의가 있을 때 [연결 해제](사유는 회원 화면에 보임)합니다.

**회원·포인트** — 이름·휴대폰·회원번호·풀팟 ID로 검색. 회원 상세에서 포인트 조정(사유 필수), 회원 정보 수정(회원번호·이름·휴대폰·이용 중지·메모), 풀팟 연결 해제, 확인 필요 지급 처리를 할 수 있습니다.

**포인트 등록 → 직접 등록**

현장이나 전화로 받은 이름과 휴대폰 번호로 회원을 바로 등록합니다.

| 칸 | 필수 | 설명 |
|---|:-:|---|
| 이름, 휴대폰 번호 | ✓ | 회원이 로그인할 때 쓰는 정보 |
| 지급 포인트, 지급 사유 | | 넣으면 등록과 함께 적립. 사유는 회원 포인트 내역에 보임 |
| APS 회원번호 | | 있으면 입력. 비우면 공식 번호와 겹치지 않는 내부 번호 `WEB-00001`부터 |

- 같은 이름(띄어쓰기 무시)·휴대폰의 회원이 이미 있으면 새로 만들지 않고, **[이 회원에게 nP 지급]** 버튼을 보여 줍니다.
- 등록 뒤에도 지급 포인트와 사유는 칸에 남아 같은 대회 참가자를 이어서 등록할 수 있습니다.
- 아래 **직접 등록 기록**에 새 회원과 기존 회원 지급이 처리자와 함께 남습니다.
- 나중에 APS 명단 파일에 같은 사람이 공식 번호로 올라오면 파일 등록이 그 행을 오류로 알려 줍니다. 회원 상세에서 회원번호를 공식 번호로 바꾼 뒤 다시 올리면 같은 회원에게 반영됩니다.

**포인트 등록 → 엑셀 파일 등록**

엑셀(.xlsx) 또는 CSV 파일을 올리면 미리보기에서 반영·새 회원·이미 반영·오류 행을 확인한 뒤 반영합니다. [양식 내려받기]로 빈 양식을 받을 수 있습니다.

| 열 | 필수 | 설명 |
|---|:-:|---|
| 회원번호 | ✓ | 예) APS-10023 |
| 포인트 | ✓ | 적립은 양수, 차감은 음수(-40). 사용 가능 포인트보다 많이 뺄 수 없음 |
| 건 번호 | ✓ | 적립 건을 구분하는 번호. **같은 회원에게 같은 건 번호는 한 번만 반영**되어 같은 파일을 다시 올려도 두 번 쌓이지 않음 |
| 이름 | | 있는 회원은 회원 기록과 같아야 반영(회원번호 오타 방지). 새 회원은 필수 |
| 휴대폰 | | 새 회원은 필수 |
| 적립일 | | 2026-10-08, 2026.10.08, 20261008, 엑셀 날짜 모두 가능. 비우면 자료 기준 시점 |
| 사유 | | 회원 포인트 내역에 보이는 내용. 예) APS 시즌2 데일리 리그 3주차 |

처음 운영을 시작할 때는 회원별 현재 잔액을 건 번호 `최초잔액`으로 한 번 올리고, 이후에는 대회별 적립 건을 올립니다. 업로드 때 정한 **자료 기준 시점**이 회원 화면의 "포인트 자료 기준"으로 보입니다. `WEB-`로 시작하는 번호로는 파일에서 새 회원을 만들 수 없습니다.

**설정** — 교환 신청 받기(켜기/끄기), 티켓 이름, 풀팟 티켓 코드, 1장당 포인트(기본 40), 한 번에 받을 수 있는 장수, 티켓 사용 안내, 지급 안내, 문의 안내. 풀팟 연동 방식(모의/API)과 응답 대기 시간도 여기서 확인합니다(바꾸는 곳은 `.env`).

## 4. 풀팟 연동 규격 (`FULPOT_MODE=http`)

즉시 연결과 즉시 지급에는 풀팟 쪽 API 세 개가 필요합니다. 아래는 이 서버가 기대하는 형태이고, 실제 풀팟 API가 다르면 `server/fulpot.js`의 `createHttpFulpot`만 맞추면 됩니다. 모든 요청에 `Authorization: Bearer {FULPOT_API_TOKEN}`을 붙이고, 8초(`FULPOT_TIMEOUT_MS`) 안에 응답이 없으면 결과를 모르는 것으로 봅니다.

```http
GET {FULPOT_API_URL}/accounts/{fulpotId}
→ 200 { "uid": "FP100231", "fulpotId": "teddy123", "nickname": "테디베어" }
→ 404 없는 ID
```

```http
POST {FULPOT_API_URL}/tickets/issues
Idempotency-Key: EX261009-0001
Content-Type: application/json

{ "requestKey": "EX261009-0001", "uid": "FP100231", "ticketCode": "TKT-APS-SAT", "quantity": 1 }

→ 200/201 { "issueId": "FPX-70001" }    지급함
→ 409     { "issueId": "FPX-70001" }    같은 requestKey로 이미 지급함(다시 주지 않음)
→ 400/404/422 { "reason": "..." }       지급 거절 → 회원 포인트 그대로
→ 그 밖(5xx, 시간 초과, 지급 번호 없는 200)  결과 모름 → '확인 필요'
```

```http
GET {FULPOT_API_URL}/tickets/issues/{requestKey}
→ 200 { "issueId": "FPX-70001", "issuedAt": "2026-10-09T08:15:00Z" }
→ 404 지급 기록 없음
```

**풀팟에 꼭 필요한 조건:** 같은 `requestKey`(신청번호)로 여러 번 요청해도 티켓은 한 번만 지급해야 합니다. 응답을 못 받은 신청을 다시 요청해도 두 번 지급되지 않는 것은 이 조건 덕분입니다. 지급은 회원이 연결할 때 풀팟이 돌려준 내부 번호(`uid`)로 요청하므로, 풀팟 ID 표기가 바뀌어도 같은 계정으로 갑니다.

## 5. 안전장치

- **두 번 지급 방지:** 신청번호를 풀팟 요청 키로 씁니다. 교환 버튼을 여러 번 누르거나 요청이 다시 들어와도 신청과 풀팟 요청은 하나뿐입니다.
- **응답을 못 받았을 때:** 포인트를 돌려주지 않고 '확인 필요'로 둔 뒤 풀팟 기록을 조회합니다. 서버가 요청 도중 멈춰 1분 넘게 '지급 중'으로 남은 신청도 확인 대상으로 옮깁니다.
- **실패 처리 보호:** 풀팟에 요청이 나가 있는 동안에는 다시 요청·완료·실패 처리를 받지 않고, 실패 처리 직전에 풀팟 기록을 다시 봅니다. 실패 처리한 건은 하루 동안 지급 기록을 계속 조회해, 풀팟의 지급이 늦게 확인되면 완료로 바로잡고 포인트를 차감합니다(장부가 실제 지급과 어긋나지 않게. 그 사이 포인트를 다른 데 썼다면 사용 가능 포인트가 음수가 될 수 있음).
- **동시 처리:** 관리자 두 명이 같은 건을 처리하면 나중에 누른 쪽은 "다른 곳에서 먼저 처리되어 지금은 '지급 완료' 상태입니다"로 막힙니다.
- **포인트:** 포인트 확인과 사용 대기 등록을 한 번에 처리해, 두 기기에서 동시에 신청해도 가진 포인트를 넘지 않습니다.
- **즉시 연결의 위험과 완화:** 승인 없이 연결하므로 다른 사람의 풀팟 ID를 알면 그 계정을 연결할 수 있고, 그러면 티켓이 그 계정으로 갑니다. 연결 전에 닉네임을 보여 주고, 한 풀팟 계정(ID와 내부 번호 모두)은 한 회원에게만 연결되며, 계정 확인은 회원당 1시간 30번으로 제한하고, 관리자가 해제할 수 있게 했습니다. 더 확실히 하려면 풀팟 로그인(OAuth)이나 풀팟 앱에서 받은 확인 코드 입력을 붙이는 것을 권합니다.
- **직접 등록:** 같은 요청은 한 번만 처리되고(요청 키), 같은 이름·휴대폰이면 새로 만들지 않으며, 내부 번호 `WEB-`는 APS 공식 번호와 섞이지 않습니다.
- 같은 이름·번호의 회원 기록이 여럿이면 자동으로 고르지 않고 운영팀 확인으로 안내합니다.
- 인증번호는 해시로만, 관리자 비밀번호는 scrypt로 저장합니다. 상태를 바꾸는 요청은 전용 헤더가 있어야 처리합니다(다른 사이트 요청 위조 방지).

## 6. 운영 서버에 올리기

1. `.env.example`을 `.env`로 복사해 채웁니다. 운영 모드(`NODE_ENV=production`)에서는 `APP_SECRET`(32자 이상 임의 문자열), 실제 문자 발송(`SMS_PROVIDER=webhook`), 풀팟 API 주소(`FULPOT_MODE=http`, `FULPOT_API_URL`)가 없으면 서버가 시작되지 않습니다. 풀팟이 발급한 토큰은 `FULPOT_API_TOKEN`에 넣습니다.
2. 관리자 계정 만들기: `npm run create-admin` (아이디·이름·비밀번호 입력). 비밀번호는 관리자 페이지 [설정]에서 바꿀 수 있습니다.
3. 서버는 HTTP로 뜨므로 앞에 HTTPS 리버스 프록시(nginx, Caddy 등)를 두고 `.env`에 `SECURE_COOKIES=1`, `TRUST_PROXY=1`, `HSTS=1`을 켭니다.
   ```
   # Caddy 예시
   points.example.com {
     reverse_proxy 127.0.0.1:3000
   }
   ```
4. **관리자 2단계 인증이 없으므로 `/admin/`과 `/api/admin/`은 사무실 IP에서만 열리도록 프록시에서 막기를 권합니다.** 비밀번호를 5번 틀리면 15분 동안 잠깁니다.
5. 프로세스는 하나만 띄웁니다(systemd, pm2 등으로 `npm start`). DB가 SQLite 파일 하나이고, 1분마다 도는 지급 확인 작업도 이 프로세스 안에서 돕니다.
6. 백업: 서버를 켠 채로 `sqlite3 data/aps.db ".backup 'backup/aps-$(date +%F).db'"`. DB에 회원 연락처가 있으므로 파일 권한을 제한하고 백업본도 안전하게 보관하세요.
7. 글꼴: Pretendard는 jsDelivr, Montserrat는 Google Fonts에서 불러옵니다(보안 헤더 CSP에 두 곳을 허용해 둠). 외부 CDN을 쓰지 않으려면 글꼴 파일을 `public/shared/`에 두고 `public/index.html`, `public/admin/index.html`과 `server/index.js`의 CSP를 바꾸세요.

### 문자 발송 연결 (`SMS_PROVIDER=webhook`)

인증번호를 보낼 때 서버가 `SMS_WEBHOOK_URL`로 아래 JSON을 POST 합니다. 문자 대행사 API 앞에 작은 중계 함수를 두고 연결하세요. 2xx가 아니거나 8초 안에 응답이 없으면 발송 실패로 안내합니다. 국내 문자 발송은 발신번호 사전 등록이 필요합니다.

```http
POST {SMS_WEBHOOK_URL}
Authorization: Bearer {SMS_WEBHOOK_TOKEN}
Content-Type: application/json

{ "to": "01012345678", "from": "{SMS_SENDER}", "text": "[APS 포인트] 인증번호는 123456입니다. 3분 안에 입력해 주세요." }
```

회원 기록에 있는 이름·번호일 때만 문자를 보내지만, 화면 응답은 같아서 가입 여부가 드러나지 않습니다.

## 7. 개발

```bash
npm test             # 30개 테스트(즉시 지급·즉시 연결·직접 등록·포인트 규칙·보안·풀팟 API 응답 처리)
npm run dev          # 파일이 바뀌면 자동 재시작
npm run build:demo   # dist/aps-web-demo.html과 맨 위 index.html 다시 만들기
```

```
server/
  index.js        HTTP 서버(정적 파일, 보안 헤더, 쿠키, 1분 정기 작업)
  app.js          요청 처리 핵심(Node 서버와 브라우저 데모가 함께 씀)
  routes.js       회원 API, 관리자 API
  fulpot.js       풀팟 연동(모의 풀팟 / 실제 API)
  services/       auth(로그인), members(회원·직접 등록), points(원장·파일 등록), exchanges(즉시 지급·확인), links(즉시 연결), settings
  db/schema.js    테이블(DB 구조 버전 2)
  sms.js          문자 발송
public/
  index.html, site/   회원 웹사이트
  admin/              관리자 페이지
  shared/             디자인 토큰(APS 색·글꼴), 공통 도구, 엑셀·CSV 읽기
scripts/          seed-demo, create-admin, build-demo
demo/             브라우저 데모 틀(sql.js로 같은 서버 코드 실행, 모의 풀팟 응답 바꾸기, 30초마다 지급 확인)
test/             core.test.js(시나리오), fulpot.test.js(풀팟 API 규격·운영 설정)
```

**포인트 계산:** 모든 증감은 원장(`ledger`)에 한 줄씩 쌓입니다. 총 보유 = 원장 합계, 사용 대기 = 지급 중·확인 필요인 교환의 포인트 합계, 사용 가능 = 총 보유 − 사용 대기. 지급이 확인되면 원장에 차감 한 줄이 추가됩니다.

**구조가 바뀐 DB:** 이번 버전은 DB 구조가 달라 이전 버전의 `data/aps.db`를 그대로 쓸 수 없습니다. 이전 DB로 켜면 서버가 시작하지 않고 안내합니다. 개발용 DB는 `npm run seed:demo -- --reset`으로 다시 만드세요.

**다음에 붙일 수 있는 것:** 풀팟 계정 소유 확인(OAuth 또는 확인 코드), 관리자 2단계 인증, 교환 내역 CSV 내려받기, 기존 APS 시스템과 잔액 연동, 공지·문의.
